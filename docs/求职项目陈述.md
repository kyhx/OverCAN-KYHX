## 二、一句话项目定位（Elevator Pitch）

> 设计并实现了一套基于 **CAN 总线**的异构多控制器嵌入式系统：以 **ESP32-S3** 为核心机负责决策、交互与数据记录，以 **STM32F103** 为分布式节点负责电机/舵机执行与温/光/红外环境感知；自定义应用层协议（帧 ID 规划、命令/状态/事件帧定义、心跳与重传、命令幂等），并实现 **CAN 固件升级（IAP Bootloader）与网关式 FOTA**，构成"感知—决策—执行"闭环，可扩展为移动小车、智能家居、农业/安防监控等形态。

## 四、项目亮点（面试中主动强调）

1. **不是单板练手，而是系统级架构**：异构 MCU 分工（ESP32 算力/交互，STM32 实时/执行），体现系统拆分能力。
2. **真实通信协议设计**：不止"能通就行"——帧 ID 按仲裁优先级规划、命令幂等、错误状态机，这是 CAN 岗的核心加分项。
3. **固件升级是技术护城河**：IAP 覆盖 flash 驱动、链接脚本、启动流程、协议分段、掉电安全、版本管理，是唯一必须有系统级视野的功能。
4. **完整闭环 + 可验证**：传感器 → 决策 → 执行 → 反馈，且每个指标都有测量方法与证据等级。
5. **软硬协同**：既写固件，也解决电源分轨（3.3V/5V）、电平匹配、终端与抗干扰等硬件问题。

## 七、面试题库

### 7.1 通用题（快速准备）

| 问题 | 答案骨架 |
| --- | --- |
| 为什么选 CAN 而不是 UART/SPI/I2C？ | 多节点、差分抗干扰、**硬件非破坏性仲裁**、工业/车载标准；UART/SPI/I2C 均为板内短距点对点或单主 |
| 为什么选 CAN 而不是 RS-485 + Modbus？ | RS-485 便宜但协议层是**主从轮询**，无法表达优先级、事件延迟不可控；CAN 原生多主 + 硬件仲裁 + 硬件级错误管理与自动重传，且**冲突不丢帧** |
| 为什么不用无线（ESP-NOW/LoRa）？ | 确定性与抗干扰；本项目有电机/舵机等强干扰源；无线重传导致延迟不可预测，实时控制不能建立在概率链路上 |
| ESP32 和 STM32 为什么这么分工？ | ESP32 有 Wi-Fi/算力做交互决策；STM32 实时 PWM/ADC 稳定且成本低。**实时控制下沉，主控不被底层中断拖垮** |
| CAN 帧结构 / 错误帧 / 位时序？ | 标准帧 11 位 ID、数据场 ≤8 字节；5 种错误类型与错误界定（主动/被动/总线关闭）；位定时（同步段/传播段/相位段）与采样点 |
| RTOS 里任务怎么划分、优先级怎么定？ | 通信/控制/交互任务，用队列/信号量解耦；优先级按**速率单调**（周期越短优先级越高）而非凭感觉 |
| I2S 音频时钟怎么配？ | MCLK/BCLK/LRCLK 关系、采样率与字长；麦克风与功放共享 BCLK/WS 必须在同一 I2S 端口 |
| 电机/舵机控制细节？ | TB6612 正反转/制动、PWM 占空比；SG90 50Hz、0.5~2.5ms 脉宽 |
| MPU6050 姿态怎么解算？ | 加速度 + 陀螺仪融合（互补滤波 / 四元数） |

### 7.2 本项目定制深挖题（面试官最可能问）

> 这些是针对本项目的设计细节，比通用八股更能体现真实动手。

**协议与总线**

1. **你的 CAN 帧 ID 是怎么分配的？为什么这么分？**
   → 按**紧急程度**而非节点顺序：类别位占高 3 位，ID 越小优先级越高 → 事件 > 命令 > 遥测 > 心跳/ACK，保证超温报警能抢占周期遥测。
2. **命令重传怎么保证不重复执行？seq 只有 8 位，撞号或节点重启了怎么办？** ⭐
   → 三条规则：① **幂等按通道判定**——广播 0x100 与单播 0x110/0x120 **各维护一个 last_seq**；若共用一个，seq 每 256 条回绕后广播与单播撞号 → 节点判为重复、只回 ACK 不执行，主站收到 ACK 却没动作，**命令静默丢失**。② **seq_valid 标志**——节点上电/软复位/OTA 跳转后 last_seq 无意义，须置 false，**第一个命令无条件执行**并记录后才启用重复判定；否则主站恰好发 seq=0 会被误判重复而丢弃。③ ACK 回显 seq，主站 50 ms 超时重传、最多 3 次。

3. **两条报文同时发送会怎样？谁赢？会不会丢？**
   → 逐位仲裁，显性位胜出；**输的一方自动转为接收并稍后重发，不丢帧**。这是 CAN 与以太网的关键差异。
4. **采样点怎么定的？为什么 87.5%？**
   → tq 与各段划分；采样点靠后保证信号经最长传播延迟后仍稳定。给出实际参数（STM32：36 MHz、P=9/BS1=6/BS2=1，8 tq/bit；ESP32：自定义 brp=20/tseg_1=6/tseg_2=1）并说明如何用示波器验证。**加分点**：知道 bxCAN 的 TS1 只有 4 bit（BS1≤16 tq，24 tq 方案不可实现）、TWAI 500K 宏默认采样点只有 80% 需自定义。
5. **8 字节怎么传 64 KB 固件？**
   → ISO-TP（SF/FF/CF/FC）或自定义分块；块级 CRC + 整包校验；窗口与流控；**推模式 vs 拉模式的取舍**。
6. **总线负载率多少？怎么算的？**
   → 111/135 bit 每帧 → 帧数/秒 × 位数 ÷ 波特率 → 当前 0.08%。**会算比数字漂亮重要。**

**架构与选型**

7. **为什么用两个不同厂商的 MCU？不是自找麻烦吗？**
   → 分层设计；代价是跨平台协议库必须零 HAL 依赖，这反而成了优势（可在 PC 单测）。
8. **ESP32-S3 的 TWAI 支持 CAN-FD 吗？**
   → **不支持，仅 Classic CAN**。要 FD 需外挂 MCP2518FD/TCAN4550（SPI）。本项目因此按 8 字节设计、用分段解决大块传输。

**硬件与电气**

9. **舵机为什么不能和 MCU 共用电源？给个数字。**
   → SG90 堵转 650~700 mA、浪涌 ~1 A；Blue Pill 板载 LDO **最大仅 300 mA**；共用会电压跌落 → 欠压复位。方案：分轨 + 共地 + 隔离二极管 + 大电容。
10. **TJA1050 直接接 3.3 V MCU 行不行？**
   → `TXD` 的 VIH ≈ 0.7×VCC = 3.5 V，3.3 V **低于规范下限**；`RXD` 5 V 推挽输出会**过压** 3.3 V 引脚。
11. **为什么 CAN 要两端各一个 120 Ω？中间为什么不加？**
    → 匹配双绞线特征阻抗以消除反射；中间加会降低等效阻抗、加重负载。加分：**分裂终端**（2×60 Ω + 4.7 nF 到地）兼顾共模抑制。
12. **500 kbps 能拉多长？支线呢？**
    → 约 100 m；支线 < 0.3 m。速率与长度成反比（往返时间须小于一个位时间）。
13. **你的 ADC 引脚能直接接 5 V 传感器的 AO 吗？**
    → **不能**。STM32F103 的模拟输入引脚不支持 5 V（即使标称 FT 的引脚，模拟模式下也不得超过 VDDA）。必须分压或改 3.3 V 供电——**这是强制项不是优化项**。

**OTA（压轴）**

14. **为什么不能原地升级？**
    → 代码 XIP，运行时从 flash 取指；擦写自己所在分区等于自毁。必须写非活动分区再切换。
15. **20 KB RAM 怎么收 64 KB 固件？**
    → **流式写入**，小缓冲边收边写 flash，不整包缓存。这引出掉电安全设计。
16. **擦 flash 的时候 CAN 会丢帧吗？** ⭐
    → 写/擦 flash 期间对 flash 的读访问会导致**总线 stall**，CAN 接收中断被推迟；页擦除量级约 20 ms，期间线上可到 8~10 帧，而 F103 的 CAN 接收**只有 3 个 FIFO 邮箱** → **会溢出丢帧**。对策：CAN ISR 放 RAM（`.ramfunc`）+ 改拉模式 + 擦除前暂停传输，并用测试用例 T-18 实测验证。
17. **升级中途断电会变砖吗？**
    → 不会。A/B 双区，活动区始终完整；整包校验通过前不写有效标志、不切换分区；标志页存双份 + CRC；两区都失效则停在 bootloader 通过 CAN 求救。
18. **怎么防止别人通过 CAN 给节点刷恶意固件？**
    → CAN 无认证 → 升级入口需**物理按键确认**；bootloader **校验固件签名**；拒绝版本降级。
19. **跳转到 App 之前要做什么？**
    → 关总中断 → 关 SysTick → 清 NVIC ICER → **清 NVIC ICPR（最易漏）** → `HAL_RCC_DeInit`/`HAL_DeInit` → `__set_MSP(*(uint32_t*)APP_ADDR)` → 跳 `APP_ADDR+4`。App 侧**最开头**必须设 `SCB->VTOR`。
20. **升级 64 KB 要多久？瓶颈在哪？**
    → CAN 传输约 1.05 s，flash 编程 + 擦除约 3 s → **瓶颈是 flash 不是总线**。所以提高波特率收益很小，优化应做传输与编程重叠。

**可靠性、RTOS 与工程**

21. **节点掉线怎么判断？误报怎么办？**
    → 3 s 无任何帧判定掉线；用 1 小时浸泡测试统计误报率；心跳 + 序列号防"假在线"。
22. **CAN 中断为什么要放 RAM 跑？**
    → 见第 16 题，flash stall 导致中断延迟。
23. **你怎么证明协议解码是对的？**
    → 协议库零 HAL 依赖 → PC 上单元测试 + **模糊测试** → CI 每次提交都跑。
24. **为什么不用 C 位域来解析 CAN 报文？**
    → C 位域的布局与字节序是**实现定义**的，跨编译器/跨平台不可靠，必须用手写移位掩码。
25. **这个项目你踩过最大的坑是什么？** ⭐
    → **必须准备一个真实、有细节的故事。** 强烈建议就用第 16 题（flash stall 丢帧），因为它有"现象 → 分析 → 验证 → 对策 → 实测"的完整链条。
