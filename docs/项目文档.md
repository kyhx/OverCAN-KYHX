- **v1.0**（2026.10.03）：**完整修订版**。保留 v0.2 及其追加的有效内容，修正其余遗留问题：
  1. **CAN 帧 ID 重规划**为 `类别(3) | 节点号(4) | 帧类型(4)`，按紧急程度排序优先级。原 `节点号<<4|帧类型` 与帧表不自洽——按该公式解码，节点一被赋予 16/17/26 三个节点号、节点二被赋予 16/18/26，且全部超出其自称的"节点号 1~15"；
  2. **修正仲裁优先级描述**：原文档称心跳 0x010 优先级最高、事件与遥测同为最低。实际上事件帧 0x110/0x120 的 ID **大于**遥测 0x101/0x102，因此**报警优先级反而低于遥测**——这与"报警应抢占上报数据"的目标相反。新方案把事件置于最高优先级、心跳/ACK 置于最低；
  3. **补全全部 10 个帧的字段定义**（原 10 个 ID 中仅 4 个有字节定义，心跳/事件/ACK 共 5 帧无定义）；
  4. 命令帧与 ACK 帧**新增序号字段**，消除"ACK 丢失→重传→重复执行"的风险；
  5. **重算总线负载率**（原 <5% 高估约 60 倍，实际 0.08%）；
  6. **功耗改为分轨预算并给出峰值**（原"总 2A"低于其自身给出的 3.1A 堵转峰值）；
  7. **拆分"命令传输时延"与"控制闭环周期"**两个指标（原混为一谈）；
  8. 新增物理层位定时/采样点、硬件缺口清单、指标证据等级列；应用场景收敛为主线 + 表格。

## 一、项目概述

基于 **CAN 总线**的分布式嵌入式系统，由 1 个核心机（总机）与 2 个功能节点组成：

| 板卡 | 核心器件 | 职责 |
| --- | --- | --- |
| **核心机** | ESP32-S3-WROOM-1（16 MB Flash / 8 MB PSRAM） | 决策调度、人机交互、数据记录、语音链路、姿态感知 |
| **节点一** | STM32F103C8T6 | 温度采集、电机驱动、声光报警 |
| **节点二** | STM32F103C8T6 | 光照采集、舵机控制、红外检测 |

三块板卡通过 **CAN 控制器 + CAN 收发器** 互联，构成一主两从结构。ESP32-S3 与 STM32F103 **均内置 CAN 控制器**（TWAI / bxCAN），**无需外挂 CAN 控制器芯片**。

**项目定位**：不是单一功能产品，而是一套"**智能头端 + 分布式执行/传感节点**"的通用控制底座。设计主线为**分布式 CAN 控制节点**，可落地为移动小车、智能家居、农业/安防监控等形态（见第十章）。

## 三、通信架构

```
                    ┌──────────────────────────────┐
                    │  核心机（总机）ESP32-S3       │
                    │  决策 / 交互 / 记录 / 语音    │
                    │  内置 TWAI 控制器             │
                    └──────────────┬───────────────┘
                                   │
                        CAN 总线 500 kbps
                     CANH / CANL 差分 ×3
                  两端各 120Ω（建议分裂终端）
                                   │
              ┌────────────────────┴────────────────────┐
              │                                         │
   ┌──────────▼──────────┐                  ┌───────────▼─────────┐
   │  节点一 STM32F103    │                  │  节点二 STM32F103    │
   │  内置 bxCAN          │                  │  内置 bxCAN          │
   │  温度 / 电机 / 蜂鸣   │                  │  光照 / 舵机 / 红外   │
   └─────────────────────┘                  └─────────────────────┘
```

- **总线类型**：CAN（控制器局域网），差分传输 CANH / CANL；**Classic CAN**（ESP32-S3 的 TWAI 不支持 CAN-FD）
- **收发器**：**TJA1050 ×3**（5V 器件；已确定保留并做电平处理：RX 先串 1kΩ 限流、不达标补 2kΩ 分压，TX 直连逐片实测，见 §9.1）；后续可换 3.3V 收发器（SN65HVD230 / MCP2562）
- **拓扑**：一主两从，节点可扩展至 15 个；**总线物理两端各接 120 Ω 终端电阻**
- **布线要求**：CAN 差分线需**绞线走线**，与动力线（电机/舵机线束）**分开布线**，避免干扰

## 四、引脚分配

### 4.1 核心机（ESP32-S3-WROOM-1）

> **不可用引脚**：
> - **GPIO 33~37**：N16R8 的 **Octal PSRAM** 占用（33=SPIIO4 … 37=SPIDQS），复用会导致总线冲突或无法启动。⚠️ **若改用 Quad PSRAM 型号（如 N8R2），这 5 个脚是可用的** —— 详见 [技术方案与实施.md](./技术方案与实施.md) 采购章节。
> - **GPIO 19 / 20**：原生 USB D-/D+，占用则无法 USB 烧写
> - **GPIO 26~32**：模组内接 SPI Flash，未引出
> - **GPIO 0**：BOOT 按键 + strapping 引脚
> - **GPIO 3 / 45 / 46**：strapping 引脚
> - **GPIO 43 / 44**：UART0 调试串口
> - **GPIO 39~42**：保留作 JTAG / SWD 调试

| 外设 | 信号 | 引脚 | 备注 |
| --- | --- | --- | --- |
| CAN（TWAI） | TX / RX | **GPIO5 / GPIO4** | GPIO 矩阵可重映射 |
| SSD1306 + MPU6050（I2C0） | SDA | GPIO1 | 与 MPU6050 同总线，地址 0x3C / 0x68 无冲突 |
| | SCL | GPIO2 | 避开 GPIO9（部分板载 BOOT 键） |
| I2S 麦克风 + 功放 | BCLK / WS | GPIO10 / GPIO11 | 见 §9.4 的两种方案取舍 |
| | DIN（←麦克风） | GPIO13 | INMP441 数据输出入 MCU |
| | DOUT（→功放） | GPIO14 | MAX98357 数据输入 |
| | SD（功放关断） | GPIO15 | 低电平关断，需拉高 |
| W25Q64（SPI2） | SCK / MOSI / MISO | GPIO16 / 17 / 18 | |
| | CS | GPIO21 | 避开 GPIO19（USB D-） |
| EC11 编码器 | A / B | GPIO6 / GPIO7 | 建议改用 PCNT 硬件计数 + 毛刺滤波 |
| 按键 ×3 | BTN1 / BTN2 / BTN3 | GPIO8 / GPIO12 / GPIO47 | 低电平有效，内部上拉 |
| 备用 | — | **GPIO9** | 唯一确定可用的备用脚 |

> ⚠️ **GPIO38 与 GPIO48 不可当作确定可用的备用脚**：板载 WS2812 的引脚**随 DevKitC-1 板卡版本在 GPIO38 / GPIO48 之间变动**，采购后须按实物核对。本表把 GPIO47 用于 BTN3，若买到 WROOM-2 系列（1.8 V 域）则 GPIO47/48 电平不符，**务必选 WROOM-1**。
> 注：GPIO4 / GPIO5 是 **CAN 专用脚**，虽可重映射，但不应计入"备用"。

> **I2C 上拉提醒**：ESP32 内部上拉约 45 kΩ，偏弱。SSD1306 + MPU6050 同总线且线长较长时，**建议在 SDA / SCL 各加 4.7 kΩ 外部上拉**（或确认模块自带上拉，避免并联后阻值过小）。

| 外设 | 信号 | 引脚 | 备注 |
| --- | --- | --- | --- |
| CAN1（bxCAN） | TX / RX | PA12 / PA11 | **PA11 与 USB D- 共用**；占用后板上 USB 不可用，调试走 SWD |

### 4.3 节点二（STM32F103C8T6）

| 外设 | 信号 | 引脚 | 备注 |
| --- | --- | --- | --- |
| CAN1（bxCAN） | TX / RX | PA12 / PA11 | 与节点一同构 |
| 光敏 | AO / DO | PA0 / PA1 | ADC1_IN0；AO 供电 5V 时须分压 |
| 红外 | AO / DO | PA2 / PA3 | ADC1_IN2；占用 PA2/PA3 即失去 USART2 |
| SG90 舵机 | PWM | **PA6（TIM3_CH1）** | 50 Hz。见下方说明 |
| （可选第二舵机） | PWM | PA7（TIM3_CH2） | 50 Hz，与第一路同定时器 |
| 调试串口 | 建议保留 USART3 | PB10 / PB11 | 或改用 SEGGER RTT |
| **SWD** | SWDIO / SWCLK | **PA13 / PA14（必须保留）** | |

> **舵机 PWM 引脚选择**：原方案用 PA8 / PA9（TIM1_CH1/CH2）。**单路舵机接 PA8 其实可用**，但把舵机移到 **TIM3（PA6 / PA7）** 有两个好处：① 释放 TIM1 高级定时器，避免与"必须使能 MOE"的复杂性纠缠；② 电机与舵机分属不同定时器，节拍互不影响。
> 注：原文档称"PA9 做第二路 50 Hz 会与 PA8 周期配置冲突"——**这一点不成立**，同一 TIM1 的两路通道共用时基，同频 50 Hz 并无冲突。改用 TIM3 是工程上更清晰的选择，而非必需。

## 五、CAN 通信协议

> 应用层协议基于 **CAN 2.0B 标准帧**（11 位 ID、8 字节数据域），物理层见第六章。
> **演进路径**：本协议为自研方案。若面向车载/工业岗位深化，建议迁移到 **CANopen（CiA-301）** —— 预定义连接集与迁移映射见 [技术方案与实施.md](./技术方案与实施.md)。

### 5.1 帧 ID 规划

**编码规则**：`ID[10:8] = 类别 | ID[7:4] = 节点号 | ID[3:0] = 帧类型`

- **类别**决定**仲裁优先级**（ID 越小越优先）：**紧急事件 > 命令 > 遥测 > 心跳/ACK**。这保证报警能抢占周期遥测与心跳。
- **节点号**：`0` = 主站/广播，`1~15` = 从节点（最多 15 个节点）
- **帧类型**：每节点每类别预留 16 个帧型

| 帧 ID | 类别 | 节点 | 方向 | 名称 | 说明 |
| --- | --- | --- | --- | --- | --- |
| **0x011** | 0 事件 | 1 | 节点一 → 主站 | 节点一事件 | 超温 / 堵转 / 故障 |
| **0x021** | 0 事件 | 2 | 节点二 → 主站 | 节点二事件 | 红外触发 / 光照越限 |
| **0x100** | 1 命令 | 0 | 主站 → 全网 | 广播命令 | 布防 / 模式切换 |
| **0x110** | 1 命令 | 1 | 主站 → 节点一 | 节点一命令 | 电机 / 蜂鸣器 |
| **0x120** | 1 命令 | 2 | 主站 → 节点二 | 节点二命令 | 舵机 / 布防 |
| **0x210** | 2 遥测 | 1 | 节点一 → 主站 | 节点一遥测 | 温度 + 执行状态 |
| **0x220** | 2 遥测 | 2 | 节点二 → 主站 | 节点二遥测 | 光照 + 红外 + 舵机 |
| **0x300** | 3 心跳 | 0 | 主站 → 全网 | 主站心跳 | 1 s 周期 |
| **0x310** | 3 ACK | 1 | 节点一 → 主站 | 节点一 ACK | 回显命令序号 |
| **0x320** | 3 ACK | 2 | 节点二 → 主站 | 节点二 ACK | 回显命令序号 |

**自洽性校验**：上表每个 ID 按 3+4+4 解码均自洽；ID 数值升序顺序（0x011 < 0x021 < 0x100 < 0x110 < 0x120 < 0x210 < 0x220 < 0x300 < 0x310 < 0x320）与紧急程度一致。
**扩展**：新增节点三只需占用节点号 3（事件 0x031 / 命令 0x130 / 遥测 0x230 / ACK 0x330），与现有 ID 无冲突。

### 5.2 帧格式（全部 8 字节数据域，**统一小端**）

> ⚠️ 解析实现**禁止使用 C 位域**（布局为实现定义，跨编译器不可靠），须用手写移位与掩码。

**0x210 节点一遥测（1 Hz）**

| 字节 | 含义 |
| --- | --- |
| 0 | 帧序号 seq（0~255 回绕，用于丢帧检测） |
| 1 | 有效位：bit0=温度、bit1=DO、bit2=电流（**bit2 待电流采样硬件，未采购前恒为 0**） |
| 2~3 | 温度 int16，单位 0.1 ℃（如 285 = 28.5 ℃） |
| 4 | 热敏 DO 状态 |
| 5 | 电机状态：0=停、1=正转、2=反转、3=制动 |
| 6 | 电机 PWM 占空比 0~100（%） |
| 7 | 状态位：bit0=堵转、bit1=过温、bit2=传感器故障 |

**0x220 节点二遥测（1 Hz）**

| 字节 | 含义 |
| --- | --- |
| 0 | 帧序号 seq |
| 1 | 有效位：bit0=光照、bit1=红外 DO、bit2=红外 AO |
| 2~3 | 光照 uint16，单位 **lux**（建议换 BH1750） |
| 4 | 红外 DO 状态 |
| 5 | 舵机当前角度 0~180（**单位：度，1° 分辨率**） |
| 6 | 红外 AO 归一化值 0~100（%） |
| 7 | 状态位 |

**0x011 / 0x021 事件帧**

| 字节 | 含义 |
| --- | --- |
| 0 | 事件码：0x01=超温、0x02=温度越限、0x03=红外触发、0x04=光照越限、0x05=堵转（**依赖电流采样硬件，未采购前不上报**）、0x06=传感器故障 |
| 1 | 事件等级：0=提示、1=警告、2=严重 |
| 2~3 | 触发值 int16（按事件码解释单位） |
| 4 | 相关通道 |
| 5~6 | 节点运行秒数低 16 位（用于事件排序） |
| 7 | **重复计数**（距上次上报的重复次数，配合 §5.3 事件风暴抑制） |

**0x100 / 0x110 / 0x120 命令帧**

| 字节 | 含义 |
| --- | --- |
| 0 | **命令序号 seq**（主站全局递增，节点回显；**广播通道与单播通道各自独立计数**，见 §5.3） |
| 1 | 命令字：0x01=设置、0x02=停止、0x03=复位、0x04=查询 |
| 2 | **设备类别**：0=电机、1=舵机、2=蜂鸣器、3=系统 |
| 3 | 通道 / 子索引（按设备类别解释） |
| 4~5 | 参数 int16（PWM 占空比 0~1000 或舵机角度 0~180） |
| 6 | 选项位 |
| 7 | 保留 |

**0x310 / 0x320 ACK 帧**

| 字节 | 含义 |
| --- | --- |
| 0 | **回显命令 seq** |
| 1 | 执行结果：0=成功，非 0=错误码 |
| 2 | 执行后状态 |
| 3~7 | 保留 |

**0x300 主站心跳（1 Hz）**

| 字节 | 含义 |
| --- | --- |
| 0 | 心跳计数 |
| 1 | 系统模式字 |
| 2~3 | 在线节点位图（bit N = 节点 N 在线） |
| 4 | 全网固件版本一致性标志 |
| 5 | **协议版本**（主站当前协议版本，节点据此判断兼容性；协议版本与固件版本分离） |
| 6~7 | 保留 |

### 5.3 可靠性与重传

| 机制 | 规则 |
| --- | --- |
| **命令应答** | 节点收到命令后回 ACK（回显 seq）；主站 **50 ms** 未收到则重传，**最多 3 次**，仍失败记故障 |
| **广播命令应答** | 广播命令（0x100）同样携带 seq；**每个在线节点各回自己的 ACK**（0x310/0x320，ID 不同故不冲突）；主站按心跳在线位图**收齐全部 ACK**，超时未齐按单节点失败处理，重传改为单播 |
| **幂等（重要）** | 节点按**通道**各维护一个"最近已执行的 seq"——**广播通道（0x100）一个、单播通道（0x110 / 0x120）一个**。**收到重复 seq 时只重发 ACK，不重复执行动作** —— 避免 ACK 丢失导致电机/舵机二次动作。⚠️ **禁止用同一个 last_seq 混用两个通道**：seq 仅 8 位、每 256 条回绕，广播与单播撞上同一 seq 会导致**命令被静默丢弃**（主站收到 ACK 却没执行） |
| **seq 有效性标志（易漏）** | 节点上电 / 软复位（含 OTA 跳转后）后 `last_seq` 无意义，必须同时置 **`seq_valid = false`**：**收到第一个命令时无条件执行**并记录 seq，之后才启用重复判定。否则主站恰好发出与节点复位默认值相同的 seq 时，命令会被误判为重复而**只回 ACK 不执行** |
| **事件风暴抑制** | 事件帧是最高优先级，无限制会饿死命令帧 → **同一事件码最小上报间隔 200 ms**；间隔内的重复事件只累加"重复计数"（事件帧 byte7），不重复发送 |
| **掉线检测** | 主站 **3 s** 内未收到某节点任何帧则判定掉线 → OLED 标红、语音告警、该节点输出置安全态（**安全态定义：电机=制动停、舵机=保持最后角度、蜂鸣器=停止**） |
| **丢帧检测** | 遥测帧携带 seq，主站统计丢失率 |
| **错误处理边界** | CAN 控制器已提供 CRC、位填充、仲裁与 ACK，应用层只处理"节点级掉线"与"命令帧丢失"，不重复实现链路层纠错 |
| **总线异常** | 须实现 Error Passive / Bus-Off 状态机与自恢复，并上报 TEC/REC 计数（见技术方案） |

> **注**：CAN 控制器的自动重传（ATR）在总线持续故障时会使发送队列阻塞，需评估是否启用限时发送/one-shot 模式，并明确其与应用层重传的关系。

## 七、RTOS 任务划分

> 核心机与节点均运行 FreeRTOS（ESP-IDF / STM32CubeMX + FreeRTOS），任务间通过队列、信号量、事件组、任务通知解耦，避免总线任务被业务阻塞。
> **优先级分配依据**：采用**速率单调（Rate-Monotonic）**原则 —— 周期越短优先级越高，而非凭感觉排序。

### 核心机（ESP32-S3）

| 任务 | 优先级 | 周期 / 触发 | 职责 | IPC |
| --- | --- | --- | --- | --- |
| CAN_RX | 高 | 收帧回调入队 | 收帧解析、按 ID 分发 | 队列 |
| CAN_TX | 高 | 队列非空 | 发命令 / 心跳，持发送互斥量 | 队列 + 互斥量 |
| Control | 中 | 10 ms | 控制策略，生成命令 | 队列、互斥量 |
| IMU | 中 | 20 ms | MPU6050 读取与姿态解算 | 队列 |
| Audio | 中 | 事件 | I2S 采集 / 播报 | 流缓冲 |
| UI | 低 | 50 ms | OLED 刷新、EC11 / 按键 | 直接 IO |
| Storage | 低 | 1 s | W25Q64 写历史曲线与日志 | SPI 互斥量 |

### 节点一 / 节点二（STM32F103）

| 任务 | 优先级 | 周期 | 职责 |
| --- | --- | --- | --- |
| CAN_RX | 高 | 中断入队 | 接收命令，**中断服务程序建议驻 RAM**（见技术方案 OTA 章节） |
| CAN_TX | 高 | 队列非空 | 发遥测 / 事件 / ACK |
| Sensor | 中 | 100 ms | ADC + DO 采集 |
| Motor / Servo | 中 | 事件 | TB6612 PWM / SG90 角度 |
| Buzzer | 低 | 事件 | 蜂鸣报警（仅节点一） |
| Heartbeat | 低 | 1 s | 运行计数、喂看门狗 |

### 栈与内存预算（20 KB SRAM 是硬约束）

STM32F103C8T6 只有 **20 KB SRAM**，任务栈必须显式分配、超出即随机崩溃：

| 用途 | 预算 |
| --- | --- |
| CAN_RX 任务栈 | 2 KB（要收帧 + 解析 + 入队，栈需求最大） |
| CAN_TX 任务栈 | 1 KB |
| Sensor 任务栈 | 1 KB |
| Motor / Servo 任务栈 | 2 KB（含 PWM 更新与串口格式化） |
| Buzzer / Heartbeat 任务栈 | 各 0.5 KB |
| 空闲任务 + TCB + 队列对象 | ≈ 3 KB |
| **任务栈合计** | **≈ 10 KB**，预留 ≥ 4 KB 给栈保护与中断嵌套 |
| 中断栈 | 由 FreeRTOS 在 SRAM 顶部分配（已在链接脚本中预留），**中断里禁止调用 printf / 浮点** |

> **落地要求**：启用 `configCHECK_FOR_STACK_OVERFLOW = 2`，运行时用 `uxTaskGetStackHighWaterMark()` 打印每个任务的剩余栈高水位（走 RTT），把水位值写进验收记录。协议库不得使用 `malloc`，避免运行时堆碎片。

> 设计要点：所有 CAN 收发集中在高优先级任务，业务任务只通过队列交互，**避免业务阻塞导致总线超时**；关键任务启用独立看门狗。

### 8.1 总线负载率计算（可复现）

**单帧位数**（Classic CAN 标准帧、8 字节数据域、含帧间间隔）：

| 情形 | 位数 |
| --- | --- |
| 无位填充 | **111 bit** |
| 最坏位填充 | **135 bit** |

**负载率 = Σ(帧数/秒 × 每帧位数) ÷ 波特率**

| 场景 | 帧数/秒 | 最坏位数/秒 | 负载率 |
| --- | --- | --- | --- |
| 当前 2 节点（心跳 1 + 遥测 2） | 3 | 405 | **0.08 %** |
| 扩到 8 节点 | 9 | 1 215 | **0.24 %** |
| 8 节点，每节点 10 Hz 遥测 | 81 | 10 935 | 2.2 % |
| 8 节点，每节点 23 Hz 遥测 | 185 | 24 975 | 5 % |
| 8 节点，每节点 92 Hz 遥测 | 740 | 99 900 | 20 % |

> 500 kbps 下理论极限约 **3 700 帧/秒**。结论：**当前负载率极低、余量充足**；真正的设计约束是固件升级时的大块传输，而非常规遥测。

## 九、关键工程约束（务必遵守）

### 9.1 CAN 收发器电平（已确定：保留 TJA1050 ×3 + 电平处理）

TJA1050 是 **5 V 器件**，与 3.3 V MCU 存在双向不兼容：

| 方向 | 问题 | 对策 |
| --- | --- | --- |
| TJA1050 → MCU（RXD） | RXD 推挽输出到 VCC=5V，直接接 3.3V 引脚**属过压**（ESP32-S3 无 5V 容忍引脚） | **先试串 1kΩ**：注入电流约 (5−3.3−Vf)/1k ≈ 1.1 mA，由 MCU 引脚 ESD 钳位二极管承受；示波器/逻辑分析仪核对高电平幅度与波形。**不达标再补 2kΩ 对地**，组成 1k/2k 分压（5V×2/3≈3.3V，节点阻抗 ~667Ω，500 kbps 下边沿无影响） |
| MCU → TJA1050（TXD） | `VIH(min)=0.7×VCC≈3.5V`，3.3V 高电平**低于规范下限**（超规格运行） | **直连 + 逐片实测**：典型阈值约 2.0~2.5V 通常能工作；每片用逻辑分析仪验证边沿与错误帧计数，先 125 kbps 再 500 kbps；不稳定的单路单独更换 |

**验证流程**：① 上电先跑 125 kbps 点对点，逻辑分析仪核对 RXD/TXD 波形幅度；② 500 kbps 连续 30 min 无错误帧（对应 T-02）；③ 短路总线制造 Bus-Off 后自恢复（对应 T-07）。任何一路出现随机错误帧，该路单独换 3.3V 收发器。

> **后续优化**：补料时可逐步替换为 SN65HVD230 / MCP2562 / TCAN332（3.3V 原生兼容，¥3~10/片），彻底消除超规格运行风险。

### 9.2 节点 Flash 容量
F103C8T6 只有 64 KB Flash、20 KB SRAM，做"Bootloader + 双 App + 标志页"会把应用压到约 24 KB，过于紧张。
→ **建议换 STM32F103CBT6（128 KB，引脚完全兼容）**，或给节点加一片 W25Q64 做双区暂存。

### 9.3 模块型号陷阱
- **1.3" OLED 多为 SH1106 而非 SSD1306**（显存 132 列），直接套用 SSD1306 驱动会整体偏移 2 像素。收货后先做 I²C 扫描并试两种驱动。
- **MPU6050 翻新/山寨货常见**：上电先读 `WHO_AM_I`(0x75) 应为 `0x68`，不符则退货。建议改用 ICM-42688-P。
- **ESP32-S3 模组版本**：务必买 **WROOM-1（3.3 V 域）**。WROOM-2 系列（N32R16V）的 GPIO47/48 属 1.8 V 的 VDD_SPI 域，与本表冲突。

### 9.4 I2S 音频链路
麦克风与功放**共享 BCLK/WS 时必须挂在同一 I2S 端口**（跨端口共用时钟引脚会冲突）。有两条合法路径：

| 方案 | 引脚 | 说明 |
| --- | --- | --- |
| (a) 单端口全双工，共享 BCLK/WS | 4~5 脚 | 省引脚；需保证 TX/RX 槽位与位宽配置一致 |
| (b) 双端口独立（I2S0 收 / I2S1 发） | 6 脚 | 更简单，无全双工耦合约束；ESP32-S3 有 2 个 I2S 控制器 |

> 本节为**架构取舍点**，建议保留两条路径的理由，而非断言其一为唯一解。

### 9.5 STM32 侧电气细节
| 项 | 约束 |
| --- | --- |
| **ADC 输入** | STM32F103 的 ADC 引脚**完全不支持 5 V**（即使标称 FT 的引脚，模拟输入也不得超过 VDDA）。热敏/光敏/红外 AO 在 5V 供电下**必须分压**；3.3V 供电可直连。这是强制项，不是优化项 |
| **TIM1 输出** | PA8/PA9 使用 TIM1（**高级控制定时器**），输出默认关闭，**必须调用 `TIM_CtrlPWMOutputs(TIM1, ENABLE)` 使能 MOE**，否则 PWM 无输出 |
| **调试串口** | 节点一 PA9 被电机 PWM 占用 → 失去 USART1；节点二 PA2/PA3 被 ADC 占用 → 失去 USART2。建议保留 USART2/USART3，或改用 **SEGGER RTT**（走 SWD，不占引脚） |
| **SWD** | **必须保留 PA13/PA14** —— 烧写与调试的唯一通道 |
| **PA11/PA12** | 兼作 USB D-/D+，用作 CAN 后板上 USB 不可用 |

### 9.6 供电与终端
- **分供电轨 + 共地**：逻辑轨（MCU / 传感器 / 收发器）与动力轨（舵机 / 电机 VM）分离；舵机电源串**肖特基二极管**（如 1N5817）+ 220 µF 电容与 MCU 轨隔离。
- 终端电阻与连接器须列入 BOM（原 BOM 缺失）。
- **注意**：终端电阻**不建议"短距就不接"** —— 缺终端会引起反射与随机误码，却表现为"通信时好时坏"，极难排查。宁可两端各装一只（成本 2 只电阻）。

### 9.7 其他工程细节
| 项 | 问题 | 对策 |
| --- | --- | --- |
| 温度精度 | 热敏模块精度约 ±1~2 ℃，非线性且需标定。**文档中的 0.1 ℃ 是分辨率，不是精度** | 明确标定方法与可达精度；建议换 DS18B20（±0.5 ℃）/ SHT30（±0.3 ℃） |
| 光照单位 | 原为无单位的 0~1000，无法验收 | 建议换 BH1750 直接输出 lux；或给出标定曲线 |
| SG90 信号电平 | 部分舵机要求 5V TTL 信号，3.3V 可能动作不可靠 | 实测；必要时加电平转换或改用 3.3V 容忍输入的舵机 |
| INMP441 数据 | 输出 24 bit 左对齐装于 32 bit 容器 | 读取后**右移 8 位**对齐，否则音量异常偏小 |
| 语音识别 | 现有硬件只能录音与播报，**不含识别能力** | 如做"听懂"需跑轻量唤醒词/命令词模型（ESP-SR）。**不得宣称离线完整语音识别** |
| FreeRTOS 栈 | 多任务并发易栈溢出 | 显式分配任务栈并用高水位标记监控 |
| 电机堵转 | 长时间堵转发热损坏 | 需加**电流采样硬件**（INA219/ACS712）+ 超时停机保护；当前 BOM 无此器件 |

## 十、应用场景

**主线：分布式 CAN 控制节点**（面向车载 / 工业 / 通信方向）。同一套"感知—决策—执行"架构可落地多种形态：

| 场景 | 硬件分工要点 | 与主线的差异 |
| --- | --- | --- |
| **移动小车 / AGV** | 节点一驱动左右轮，核心机 MPU6050 提供航姿，节点二红外避障 | 增加运动控制与航向推算 |
| **智能家居中控** | 语音指令 → 核心机解析 → CAN 下发节点执行 | 增加 Wi-Fi 上云 |
| **温室 / 农业监控** | 节点一温控 + 风机，节点二光照 + 遮阳卷帘，核心机记录曲线 | 强调长期数据记录 |
| **安防报警** | 节点二红外入侵检测，节点一蜂鸣告警，核心机语音喊话 | 强调事件实时性 |
| **助老助残辅助** | 语音交互为主，节点完成推送 / 开关动作 | 强调交互易用性 |

**典型闭环**（农业监控）：温度超限 → 节点一事件帧（0x011）→ 主站决策 → 命令帧（0x110）开风机 → 节点回 ACK（0x310）→ 遥测（0x210）反馈温度下降。

**场景共性**：CAN 承载通信（节点可持续挂载、总线不变）；算力分层（ESP32 决策 / STM32 执行，实时控制下沉）；交互多样（语音 + 屏 + 编码器 + 按键）；闭环完整（温 / 光 / 红外感知 + 电机 / 舵机执行）。

> **简历叙事建议**：只选 **1 个**主方向（分布式 CAN 控制节点）作为故事主线，其余用一句"已可拓展为……"带过。六个场景全写会显得项目发散。

## 十一、可行性、风险与缺口

### 11.1 可行性结论

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| CAN 通信 | ✅ 可行 | ESP32-S3 内置 1 个 TWAI（1K~1Mbps、标准/扩展帧、64 字节 RX FIFO）；STM32F103 内置 bxCAN。**无需外挂 MCP2515** |
| 多外设并发 | ✅ 可行 | 芯片资源远超需求（2×I2S、4×SPI、2×I2C、LEDC、PCNT、ADC） |
| 算力分层 | ✅ 可行 | 240 MHz 双核 LX7 + 8 MB PSRAM + 16 MB Flash |
| 实时控制 | ✅ 可行 | 72 MHz STM32F103 + 硬件 PWM，控制周期可达 1 ms 级 |
| 协议可扩展性 | ✅ 可行 | 新编码规则下节点号 1~15，ID 唯一性可逐条校验 |
| 指标可信度 | ❌ **待验证** | 全部指标为分析级，无实测 |
| 成本 | ✅ 可行 | 全系统约 ¥310~560（不含打样与仪器） |

### 11.2 阻塞项（必须解决，P0）

| # | 问题 | 方案 |
| --- | --- | --- |
| ① | **CAN 收发器 5V/3.3V 不兼容**（TJA1050 ×3 在用） | **已确定保留**：RX 先串 1kΩ 限流（不达标补 2kΩ 分压）+ TX 逐片实测（§9.1）；不稳定单路单独换 3.3V 收发器 |
| ② | **N16R8 的 GPIO33~37 被 Octal PSRAM 占用** | 引脚表已避让；**或改用 Quad PSRAM 型号（N8R2）释放这 5 个脚** |
| ③ | **舵机/电机供电能力不足**（堵转合计 ≥3.1 A） | 分轨供电 + 独立 5V/5A 电源 + 隔离 + 共地 |
| ④ | **ADC 通道不允许 5 V 输入** | AO 必须分压或改 3.3 V 供电（强制项） |
| ⑤ | **升级可能导致变砖**（F103 无双 bank、仅 20 KB SRAM） | A/B 双区 + 整包校验 + 有效标志双份（见技术方案） |

### 11.3 硬件缺口清单

| 缺失 | 影响的功能 | 建议补充 |
| --- | --- | --- |
| 电流采样（INA219 / ACS712） | 原承诺"固件加堵转电流检测"，但无采样器件 | 加 1 路电流采样 + 超时保护 |
| 编码器 | 原承诺"电机 PID"，但无转速反馈 | 加正交编码器（用 TIM 编码器模式） |
| RTC（DS3231） | 历史曲线与事件日志无绝对时间基准 | 加 I²C RTC |
| USB-CAN 分析仪 | **无法自证 CAN 通信正确性、无法做故障注入** | 强烈建议采购（¥60~120） |
| CAN 终端电阻 + 连接器 | 未列入 BOM | 120 Ω ×2（或分裂终端）+ 端子/DB9 |
| 独立动力电源 + DC-DC | 文档要求但未列规格 | 5V/5A 电源 + 逻辑 LDO |
| SWD 调试排针 | 未保留 | 两节点各留 PA13/PA14 |
| 模块备件 | 单点故障导致停工 | 关键器件多买 1~2 个 |

### 11.4 最大风险：范围与成熟度

**技术可行性高，但项目成熟度低** —— 当前没有固件代码、没有实测数据、没有版本控制仓库。文档中的"已完成"均指**章节撰写完成**，不代表功能实现。

## 十二、路线图

详细技术方案、OTA 设计、工具链、采购防坑与验收测试用例见 **[技术方案与实施.md](./技术方案与实施.md)**。

| 阶段 | 周期 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| 1. 单节点打通 | 1 周 | 节点一固件 | ADC 读数与数字传感器对比误差 < 1 ℃；PWM 示波器可测 |
| 2. 点对点 CAN | 1 周 | 两板互通 + **擦 flash 丢帧先行实验** | 分析仪抓到正确帧；连续 30 min 无错误帧；**丢帧率入库（定 bootloader 架构）** |
| 3. 协议层 | 2~3 周 | 协议库 + DBC + PC 单元测试 | 10/10 帧有定义；单元测试与模糊测试通过；CI 绿 |
| 4. 主站接入 | 1~2 周 | 心跳、掉线检测、ACK+重传+幂等 | 掉线 3 s 内检出；1 h 浸泡 0 误报；重复命令不重复执行 |
| 5. 供电与执行机构 | 1 周 | 分轨供电 + 电机/舵机 | 舵机堵转时 MCU 不复位（3.3V 轨跌落 < 100 mV） |
| 6. 闭环控制 | 2 周 | 编码器 + 速度环 PID | 阶跃响应指标写入文档 |
| 7. 固件升级 | 2~3 周 | CAN Bootloader + OTA | 掉电中断 10 次不变砖；升级不丢帧 |
| 8. 健壮性与实测 | 1~2 周 | 故障注入测试 + 指标回填 | 全部指标替换为实测值 |

**合计约 12~16 周**（业余时间）。若时间有限，优先保证阶段 1~5 与 8。

> ⚠️ **验收标准对未采购硬件的依赖**：阶段 6（编码器闭环）、阶段 9（RTC 时间戳）、阶段 6 与 T-11（电流采样）依赖的**编码器、RTC、电流采样器件均未采购**（见 §11.3）。未补齐时对应验收降级为：开环 PWM + 超时停机保护 + 相对时间基准，**不得在简历中宣称闭环 PID / 堵转电流检测**。
