## 二、术语、字节序与位序约定

| 约定 | 规定 |
| --- | --- |
| 帧格式 | CAN 2.0B **标准帧**（11 位 ID、DLC 0~8），**不使用扩展帧** |
| 字节序 | 多字节字段一律 **小端（Intel）**：低字节在低偏移 |
| 位序 | 单字节内的位以 **bit0 = LSB** 编号；跨字节无位域 |
| 位域实现 | ⛔ **禁止使用 C 位域**解析报文（布局为实现定义，跨编译器不可靠）→ 一律手写移位与掩码（协议库 `proto_bytes.h` 已封装） |
| 浮点 | 报文内**无浮点**，全部定点整数（避免跨平台格式与 FPU 差异） |
| 内存 | 协议库**不使用 `malloc`**，全部栈上结构体；可重入、无全局可变状态（幂等状态由调用方持有） |
| 依赖 | 协议库**零 HAL 依赖**（纯 C99）：可在 PC 上单元测试，被两块不同 MCU 共用 |
| 物理层 | 500 kbps · 采样点 87.5%（参数见 [项目文档.md](./项目文档.md) §6） |

**本文出现的记号**：`b0` = 数据场字节 0；`b2..b3` = 字节 2 与 3 组成的小端 16 位；`bit N` = 该字节第 N 位。

## 三、帧 ID 规划（3 + 4 + 4）

### 3.1 编码规则

```
ID[10:8] = 类别 category   (3 bit)   —— 决定仲裁优先级，ID 越小越优先
ID[7:4]  = 节点号 node     (4 bit)   —— 0 = 主站/广播，1~15 = 从节点
ID[3:0]  = 帧类型 type     (4 bit)   —— 每类别每节点预留 16 个帧型
```

**类别与紧急度**（这是本协议的核心设计决定）：

| 类别 | 值 | 优先级 | 理由 |
| --- | --- | --- | --- |
| 事件 EVENT | 0 | **最高** | 超温 / 堵转 / 入侵等报警必须能抢占周期数据 |
| 命令 COMMAND | 1 | 高 | 控制指令的时效性仅次于报警 |
| 遥测 TELEMETRY | 2 | 低 | 1 Hz 周期数据，晚一个周期无实质损失 |
| 心跳/ACK HEARTBEAT_ACK | 3 | **最低** | 心跳与确认可以等；ACK 迟到只触发重传，不影响安全 |

**帧类型语义**（统一编号，避免"type 字段语义漂移"这一经典缺陷）：

| type | 含义 | 适用类别 |
| --- | --- | --- |
| 0 | 常规帧 | 命令 / 遥测 / 心跳 / ACK |
| 1 | 事件帧 | 事件 |
| 2~15 | **保留**（新增帧型时按序分配，禁止复用已废弃值） | 全部 |

> 一致性规则：`type` 是**帧型分类**，不是任意编号。校验函数 `proto_make_id()` / `proto_id_is_valid()` 已把这条规则编码进代码。

### 3.2 帧清单（10 帧，全部已定义）

| 帧 ID | 类别 | 节点 | 方向 | 名称 | DLC | 速查 |
| --- | --- | --- | --- | --- | --- | --- |
| **0x011** | 0 事件 | 1 | 节点一 → 主站 | NODE1_EVENT | 8 | §5.2 |
| **0x021** | 0 事件 | 2 | 节点二 → 主站 | NODE2_EVENT | 8 | §5.2 |
| **0x100** | 1 命令 | 0 | 主站 → 全网 | CMD_BROADCAST | 8 | §5.3 |
| **0x110** | 1 命令 | 1 | 主站 → 节点一 | CMD_NODE1 | 8 | §5.3 |
| **0x120** | 1 命令 | 2 | 主站 → 节点二 | CMD_NODE2 | 8 | §5.3 |
| **0x210** | 2 遥测 | 1 | 节点一 → 主站 | TELEMETRY_NODE1 | 8 | §5.1 |
| **0x220** | 2 遥测 | 2 | 节点二 → 主站 | TELEMETRY_NODE2 | 8 | §5.1 |
| **0x300** | 3 心跳 | 0 | 主站 → 全网 | MASTER_HEARTBEAT | 8 | §5.4 |
| **0x310** | 3 ACK | 1 | 节点一 → 主站 | ACK_NODE1 | 8 | §5.4 |
| **0x320** | 3 ACK | 2 | 节点二 → 主站 | ACK_NODE2 | 8 | §5.4 |

**数值升序校验**：0x011 < 0x021 < 0x100 < 0x110 < 0x120 < 0x210 < 0x220 < 0x300 < 0x310 < 0x320 —— 与紧急度完全一致。
**广播优先**：广播命令 0x100 < 单播 0x110/0x120，故广播在仲裁中**天然先于**单播发送（这是有意设计，不是巧合）。

**节点扩展**：新增节点 k（k = 3~15）占用 事件 `0x0k1` / 命令 `0x1k0` / 遥测 `0x2k0` / ACK `0x3k0`，与现有 ID 无冲突。节点三示例：0x031 / 0x130 / 0x230 / 0x330。

## 四、通用字段规范

### 4.1 命令序号 seq（可靠性基石）

| 项 | 规定 |
| --- | --- |
| 位宽 | **uint8**，0~255 **回绕** |
| 生成方 | **仅主站**。命令帧携带 seq |
| 计数器 | **按通道独立计数**——广播通道（0x100）一个、单播通道（0x110/0x120）一个 |
| 回显 | ACK 帧 b0 原样回显 seq（主站据此匹配是哪一个命令被确认） |
| 重复判定 | 见 §7.2 幂等状态机 |

> ⚠️ **为什么必须按通道分离**：seq 只有 8 位，每 256 条命令回绕。若广播与单播共用一个计数器，主站发广播 `seq=7`（两节点 last_seq=7）后再发单播 `seq=7`，节点会判定为重复 → **只回 ACK 不执行** → 主站收到 ACK 却没有任何动作发生，命令**静默丢失**。这是本项目在 v1.4 修复的真实缺陷。

### 4.2 遥测帧序号 seq

遥测帧自带 b0 = seq（0~255 回绕），**仅用于丢帧率统计**（主站观察序列缺口），不参与幂等判定。与命令 seq 是**两个独立计数器**，互不影响。

### 4.3 单位与标度（全协议统一）

| 物理量 | 编码 | 单位 | 说明 |
| --- | --- | --- | --- |
| 温度 | int16 | **0.1 ℃** | 例：285 = 28.5 ℃；−55 = −5.5 ℃ |
| 光照 | uint16 | **lux** | 建议硬件换 BH1750 直读 lux |
| 归一化百分比 | uint8 | **%** | 0~100 |
| 舵机角度 | uint8 | **度** | 0~180（超出即拒收，见 §4.4） |
| 电机 PWM | uint8 | **%** | 0~100；命令帧内使用 0~1000 的 int16 精细标度 |
| 运行时间 | uint16 | **秒** | 低 16 位，用于事件排序 |

### 4.4 解码期校验（必须实现的硬约束）

| 校验 | 错误码 | 处理 |
| --- | --- | --- |
| DLC 与帧类型不符 | `PROTO_ERR_LEN` | 丢弃 + 计数 |
| ID 的节点号与本节点不符 | `PROTO_ERR_NODE` | 丢弃（正常应被硬件验收滤波器拦掉，双重保险） |
| 命令参数越界（如舵机 > 180、占空比 > 1000） | `PROTO_ERR_RANGE` | **拒收，不执行**，回 ACK 带错误码；**绝不静默截断** |
| 命令字 / 设备类别 / 事件码为未定义值 | `PROTO_ERR_VALUE` | 丢弃 + 计数 |
| 保留字节非 0 | — | **忽略**（不校验），保证前向兼容 |

> **设计原则**：越界参数**拒绝执行**而不是截断到边界——截断会让"主站以为转了 90°，实际转了 180°"这类错误无法被发现。

## 五、逐帧字节布局

> 全部 **8 字节**。表中"字节"列即数据场偏移。未列出的位为**保留位/保留字节，发送方置 0，接收方忽略**。

### 5.1 遥测帧（1 Hz 周期）

#### 5.1.1 `0x210` TELEMETRY_NODE1（节点一 → 主站）

| 字节 | 字段 | 位宽 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- | --- |
| b0 | `seq` | 8 | uint8 | — | 遥测序号，用于丢帧统计 |
| b1 | `valid` | 8 | bitfield | — | bit0=温度有效、bit1=DO 有效、bit2=电流有效（**待电流采样硬件，未采购前恒 0**）、bit3~7 保留 |
| b2..b3 | `temperature` | 16 | **int16** | 0.1 ℃ | 有符号！负温必须正确表示 |
| b4 | `do_state` | 8 | uint8 | — | 热敏模块数字量输出（0/1） |
| b5 | `motor_state` | 8 | enum | — | 0=停、1=正转、2=反转、3=制动（见附录 A） |
| b6 | `motor_duty` | 8 | uint8 | % | 当前占空比 0~100 |
| b7 | `status` | 8 | bitfield | — | bit0=堵转（**待硬件**）、bit1=过温、bit2=传感器故障、bit3~7 保留 |

> **与上位文档的协调项**：位域中 bit0 堵转、bit2 电流目前依赖**未采购的电流采样器件**（见 [项目文档.md](./项目文档.md) §11.3）。硬件补齐前这些位**恒为 0 且不得据此判定故障**，避免"永远不报警"被误读为"从未堵转"。

#### 5.1.2 `0x220` TELEMETRY_NODE2（节点二 → 主站）

| 字节 | 字段 | 位宽 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- | --- | --- |
| b0 | `seq` | 8 | uint8 | — | 遥测序号 |
| b1 | `valid` | 8 | bitfield | — | bit0=光照、bit1=红外 DO、bit2=红外 AO |
| b2..b3 | `light` | 16 | uint16 | lux | 0~65535（BH1750 满量程内足够） |
| b4 | `ir_do` | 8 | uint8 | — | 红外数字量（0/1） |
| b5 | `servo_angle` | 8 | uint8 | 度 | 0~180 |
| b6 | `ir_ao_pct` | 8 | uint8 | % | 红外模拟量归一化 |
| b7 | `status` | 8 | bitfield | — | **待定义**——当前上位文档仅写"状态位"，未分配具体位。硬件未定前发送 0，接收方忽略 |

### 5.2 事件帧（最高优先级）

`0x011` NODE1_EVENT / `0x021` NODE2_EVENT —— 仅方向与 ID 不同，布局相同：

| 字节 | 字段 | 位宽 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| b0 | `event_code` | 8 | enum | 0x01=超温、0x02=温度越限、0x03=红外触发、0x04=光照越限、0x05=堵转（**待硬件**）、0x06=传感器故障 |
| b1 | `level` | 8 | enum | 0=提示、1=警告、2=严重 |
| b2..b3 | `value` | 16 | **int16** | 触发值，单位**按事件码解释**（超温/温度越限 = 0.1 ℃；光照越限 = lux；堵转 = mA） |
| b4 | `channel` | 8 | uint8 | 相关通道（传感器编号 / 电机通道），0 表示不区分 |
| b5..b6 | `uptime_s` | 16 | uint16 | 节点运行秒数低 16 位（用于事件先后排序，**不是绝对时间**） |
| b7 | `repeat_count` | 8 | uint8 | 距上次上报同码事件的重复次数（配合 §7.4 风暴抑制，饱和于 255） |

> **事件帧不带 seq**：它是一次性状态变化通知，不是可重发的命令。去重靠"事件码 + `repeat_count` + 风暴抑制窗口"，而非序号比对。

### 5.3 命令帧

`0x100` CMD_BROADCAST（node=0）/ `0x110` CMD_NODE1 / `0x120` CMD_NODE2 —— 布局相同：

| 字节 | 字段 | 位宽 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| b0 | `seq` | 8 | uint8 | **命令序号**（按 §4.1 通道独立计数；ACK 原样回显） |
| b1 | `cmd` | 8 | enum | 0x01=设置、0x02=停止、0x03=复位、0x04=查询 |
| b2 | `device` | 8 | enum | 0=电机、1=舵机、2=蜂鸣器、3=系统 |
| b3 | `channel` | 8 | uint8 | 通道 / 子索引，按设备类别解释 |
| b4..b5 | `param` | 16 | **int16** | 参数：PWM 占空比 **0~1000**（即 0.1% 分辨率）或舵机角度 **0~180** |
| b6 | `options` | 8 | bitfield | 选项位（当前未定义，置 0） |
| b7 | — | 8 | — | 保留，置 0 |

**参数范围（按设备类别，解码期强制校验）**：

| `device` | `param` 合法范围 | 越界错误码 |
| --- | --- | --- |
| 0 电机 | 0 ~ 1000 | `PROTO_ERR_RANGE` |
| 1 舵机 | 0 ~ 180 | `PROTO_ERR_RANGE` |
| 2 蜂鸣器 | 0 ~ 1000 | `PROTO_ERR_RANGE` |
| 3 系统 | 不限（语义由 cmd 决定，负数合法） | — |

### 5.4 ACK 帧

`0x310` ACK_NODE1 / `0x320` ACK_NODE2：

| 字节 | 字段 | 位宽 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| b0 | `echo_seq` | 8 | uint8 | **回显命令 seq**（主站据此匹配命令） |
| b1 | `result` | 8 | enum | 0=成功；非 0 = 错误码（复用 §11 错误码枚举） |
| b2 | `state` | 8 | uint8 | 执行后设备状态（如执行后的电机状态 / 舵机角度） |
| b3..b7 | — | — | — | 保留，置 0 |

### 5.5 心跳帧

`0x300` MASTER_HEARTBEAT（主站 → 全网，1 Hz）：

| 字节 | 字段 | 位宽 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| b0 | `heartbeat_count` | 8 | uint8 | 心跳计数，回绕；主站周期性递增，节点可据此判断主站是否卡死 |
| b1 | `system_mode` | 8 | bitfield | 系统模式字（布防/撤防/调试等，当前未定义，置 0） |
| b2..b3 | `online_bitmap` | 16 | uint16 | 在线节点位图：**bit N = 节点 N 在线** |
| b4 | `fw_version_uniform` | 8 | uint8 | 全网固件版本一致性标志：0=一致、非 0=存在不一致 |
| b5 | `protocol_version` | 8 | uint8 | **协议版本**（与固件版本分离，见 §10） |
| b6..b7 | — | — | — | 保留，置 0 |

> **节点没有心跳帧**：节点的存在性由"周期性遥测帧（1 Hz）"体现。这符合 [项目文档.md](./项目文档.md) §5.3 的掉线判定（3 s 内未收到**任何**帧即判掉线），也省掉了一个帧型。
> **位图定义**：`bit N` 对应**节点号 N**（不是 ID 索引）——`bit1` = 节点一。约定与 ID 编码的 node 字段一致，避免两套编号。

## 六、仲裁优先级实测语义

| 冲突场景 | 结果 |
| --- | --- |
| 事件 vs 命令 | 事件赢（ID 0x011 < 0x100），报警抢占控制指令 |
| 广播命令 vs 单播命令 | 广播赢（0x100 < 0x110），全网动作先落地 |
| 命令 vs 遥测 | 命令赢（0x1xx < 0x2xx） |
| 遥测 vs 心跳/ACK | 遥测赢（0x2xx < 0x3xx） |
| 节点一 vs 节点二（同类别） | node 字段较小者赢（0x110 < 0x120），**随机性被消除** |
| 两帧完全相同 ID | 逐位仲裁涉及 ID 之后的 RTR/IDE/DLC 与数据场；若完全一致则两者都成功（不与以太网相同） |

> 输掉仲裁的一方**自动转为接收并在总线空闲后重发，不丢帧**——这是 CAN 相对以太网的关键差异，也是本项目选择 CAN 的核心理由之一。

## 七、可靠传输与状态机

### 7.1 发送侧（主站）

```
发命令(seq) ──► 启动 50 ms 定时器
     │
     ├─ ACK(echo_seq == seq) 到达 ──► 成功，停止定时器
     │
     └─ 超时 ──► 重传同一 seq（重传次数 +1）
                   └─ 重传 3 次仍无 ACK ──► 记故障，上报用户
```

| 参数 | 值 | 宏（`proto_seq.h`） |
| --- | --- | --- |
| ACK 超时 | 50 ms | `PROTO_ACK_TIMEOUT_MS` |
| 最大重传 | 3 次（首次 + 3 次重传 = 最多 4 次发送） | `PROTO_ACK_MAX_RETRY` |

**广播命令的应答语义**：广播 0x100 同样携带 seq，**每个在线节点各回自己的 ACK**（0x310/0x320 ID 不同，不冲突）。主站按心跳 `online_bitmap` **收齐全部 ACK**；超时未收齐即按"部分节点失败"处理，**重传改为单播**（逐个补发），避免广播风暴。

### 7.2 接收侧幂等状态机（**最关键的正确性逻辑**）

节点为**每个通道分别**持有一个状态：

```
状态 = { last_seq[通道], seq_valid[通道 ×] }
  通道 A = 广播 (0x100)
  通道 B = 单播 (0x110 / 0x120)
```

```
收到命令(ch, seq):
    若 !seq_valid[ch]:                     # 上电 / 软复位 / OTA 跳转后
        → 无条件执行
        → last_seq[ch] = seq; seq_valid[ch] = true
        → 回 ACK(result = OK)
    否则若 seq == last_seq[ch]:
        → **不执行**，只重发 ACK(result = OK)      # 重复命令
    否则:
        → 执行; last_seq[ch] = seq
        → 回 ACK(result = OK)
```

**两条铁律**（本项目 v1.4 修复的真实缺陷，不可简化）：

1. **按通道分离 `last_seq`** —— 共用一个计数器时，8 位 seq 每 256 条回绕，广播与单播必然撞号 → 命令**静默丢失**（主站收到 ACK 却没有动作）。
2. **`seq_valid` 标志** —— 复位后 `last_seq` 无意义（默认 0）。若主站恰好发出 `seq=0`，节点会误判重复而**只回 ACK 不执行**。因此第一个命令必须**无条件执行**，之后才启用重复判定。

> 重传语义与幂等语义的分工：**重传保证"至少一次"到达，幂等保证"至多一次"执行**。两者缺一，要么命令丢失，要么执行器二次动作（电机重启、舵机跳变）。

### 7.3 掉线检测与安全态

| 项 | 规定 |
| --- | --- |
| 判定 | 主站 **3 s** 内未收到某节点**任何帧** → 判定掉线 |
| 表现 | OLED 标红 + 语音告警 + 节点表标记离线 |
| **安全态** | 电机 = **制动停**（不是自由滑行）、舵机 = **保持最后角度**、蜂鸣器 = **停止** |
| 误报要求 | 1 小时浸泡测试 0 误报（验收 T-04） |

> 安全态按执行器分别定义，而不是笼统的"停止输出"：舵机断电会因负载掉落而改变角度，反而危险；电机应制动而非滑行。

### 7.4 事件风暴抑制

事件帧是最高优先级，若同一事件持续触发（如温度一直超限）而无限制上报，会**饿死命令帧**。

| 规则 | 值 |
| --- | --- |
| 同一事件码最小上报间隔 | **200 ms** |
| 间隔内的重复事件 | **不发送**，仅累加 `repeat_count`（b7），下次上报时一并带出 |
| 计数器饱和 | 255（不再回绕，避免"重复了 0 次"的歧义） |

### 7.5 主站心跳与 CAN 控制器状态

- 节点通过 0x300 判断主站存活；`heartbeat_count` 长时间不变 = 主站任务卡死。
- **Error Passive / Bus-Off 状态机**：总线错误累积到阈值时控制器进入错误被动/Bus-Off。**必须实现**：读 TEC/REC 计数、Bus-Off 后按规范执行恢复序列（128 次 11 位隐性位后自动恢复 + 软件重初始化）、期间上报故障。**验收 T-07** 要求短路总线后能自动恢复。
- **自动重传（ATR）与 one-shot 的取舍**：ATR 在总线持续故障时会让发送队列阻塞；应用层已有重传机制，因此**故障注入场景下评估启用 one-shot（限时发送）**，并明确它与 §7.1 应用层重传的关系（不与链路层重传叠加成无限重试）。

## 八、方向性与合法性校验矩阵

每个节点**必须**在应用层再次校验（硬件验收滤波器是第一道防线，见 §9）：

| 收到帧 | 合法发送方 | 非法来源的处理 |
| --- | --- | --- |
| 0x011 / 0x021 事件 | 对应节点 | 主站侧：非在位图节点上报 → 丢弃并记安全事件 |
| 0x100 广播命令 | **仅主站** | 节点侧无法区分来源（CAN 无认证）→ 依赖 §9 威胁缓解 |
| 0x110 / 0x120 单播命令 | 仅主站 | 同上 |
| 0x210 / 0x220 遥测 | 对应节点 | 主站侧：ID 与在位节点不符 → 丢弃 |
| 0x300 心跳 | 仅主站 | 节点侧：非预期 → 丢弃 |
| 0x310 / 0x320 ACK | 对应节点 | 主站侧：echo_seq 无对应在途命令 → 忽略（可能是超时后迟到的 ACK） |

> **迟到的 ACK**：主站超时重传后可能先收到旧 ACK。因此匹配必须用 **seq + "该 seq 仍在途"** 双重条件，而不是"收到任意 ACK 就算成功"。

## 九、安全边界（明确不承诺的）

CAN 天生**无发送者认证、无加密、广播可监听**，CAN 自身 CRC 只防传输错误**不防恶意篡改**。因此：

- 任何能物理接入总线的设备**都可以伪造任意 ID**。协议层**不宣称**能识别伪造节点。
- 缓解手段（分层，见 [技术方案与实施.md](./技术方案与实施.md) §5）：
  1. **硬件验收滤波器**（bxCAN 14 组 / TWAI acceptance filter）做 ID 白名单，非法 ID **在控制器层丢弃，不进中断**；
  2. 网关侧数据范围校验（温度突变、参数越界）；
  3. **固件升级需物理按键确认 + bootloader 校验签名**——本协议的抗攻击重心在固件升级链路，而非报文认证；
  4. 版本号单调递增，拒绝降级。

## 十、协议版本与兼容性

| 项 | 规定 |
| --- | --- |
| 当前协议版本 | **1**（心跳 b5 = `protocol_version`） |
| 与固件版本的关系 | **完全分离**。固件可升级而不改协议；协议变更必须递增此字段 |
| 兼容判定 | 节点收到心跳 b5 ≠ 自身支持版本时：**降级为安全子集运行**（只收发共同版本字段）并上报版本不匹配事件；不得按新格式强行解析旧节点报文 |
| 破坏性变更定义 | 字段含义变化、位宽缩减、事件码/命令码复用、DLC 变化 |
| 非破坏性变更 | 追加新的命令字 / 事件码 / 帧类型（接收方按 §4.4 忽略未知值）；**保留位启用**（发送方置 0 的位被赋予含义即属破坏性，需谨慎） |

## 十一、错误码枚举（全协议统一）

| 值 | 名称 | 含义 | 出现位置 |
| --- | --- | --- | --- |
| 0 | `PROTO_OK` | 成功 | ACK b1 |
| 1 | `PROTO_ERR_LEN` | DLC 与帧类型不符 | 解码返回 |
| 2 | `PROTO_ERR_ID` | 帧 ID 不符合 3+4+4 规则或未定义 | 解码返回 |
| 3 | `PROTO_ERR_NODE` | 节点号不是本节点 | 解码返回 |
| 4 | `PROTO_ERR_RANGE` | 参数越界（**拒收不执行**） | 解码返回 / ACK b1 |
| 5 | `PROTO_ERR_VALUE` | 枚举值未定义（命令字/设备/事件码） | 解码返回 / ACK b1 |
| 6 | `PROTO_ERR_STATE` | 当前状态不允许该操作 | ACK b1 |
| 7 | `PROTO_ERR_BUSY` | 设备忙（如升级中） | ACK b1 |
| 8 | `PROTO_ERR_CRC` | 块级/整包 CRC 校验失败 | 升级链路 |
| 9 | `PROTO_ERR_UNSUPPORTED` | 功能未实现（如无电流采样时的堵转查询） | ACK b1 |

## 十二、实现检查清单（自查用）

- [ ] 解码前先校验 DLC，再校验 ID 合法性，最后校验取值范围（顺序不可颠倒）
- [ ] **不使用 C 位域**；每个位域读写都经过 `proto_bytes.h` 的封装
- [ ] 幂等状态**按通道**分离，`seq_valid` 复位后置 false
- [ ] 越界参数**拒收并回错误 ACK**，不静默截断
