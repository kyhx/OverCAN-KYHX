## 协议定义源与"DBC 不脱节"机制（勿破坏）

- **单一定义源 = `proto_id.h` 里的 `PROTO_FRAME_TABLE`**（每行 ID/名称/方向/DLC/周期）。DBC 由 `tools/gen_dbc.py` 从它生成；`tests/test_dbc_drift.c` 每次构建重解析该头文件并与 DBC 文本比对；`tools/validate_dbc.py` 用 cantools 解码"黄金报文"与 C 库对拍。**改协议后必须跑 `python tools/gen_dbc.py --write`**，否则 `dbc_generator_in_sync` 会失败。
- 解析边界是 `PROTO_FRAME_TABLE_BEGIN/END` 标记注释；**该注释附近的说明文字不得出现形如 `{ 0x…, "…" }` 的字面示例**——生成器的正则与 C 测试的解析器都会把它当成一条表项（本项目已踩过）。
- 构建命令：`cmake -S . -B build && cmake --build build --config Debug && ctest --test-dir build -C Debug --output-on-failure`。
- 工具链实测可用：**MSVC 14.51**（`C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools`，CMake 自动发现；必须加 `/utf-8`，否则中文注释报 C4819 且可能截断）、CMake 4.4.3、Python 3.14 + cantools 44.1、git 2.55。**注意增量编译不可靠**：改完头文件若测试仍报旧错误，删 `build/` 重新配置。

## 本次落地抓出的 4 个真实缺陷（面试可讲"被测试抓出来"）

1. **CRC-32 用了非反射多项式** `0x04C11DB7` 右移 → 结果不是标准值；必须用**反射形式 `0xEDB88320`**。由 `"123456789"` 标准校验值 0xCBF43926 抓出。
2. **`node < PROTO_NODE_MIN` 的整型提升**：`node` 是 `uint8_t`，与枚举常量比较被提升为 int，`node=0` 被误判"小于下界" → 主站帧被判非法。须显式 `(unsigned)` 比较。
3. **心跳与 ACK 共用 `HEARTBEAT_ACK` 类别**：把"必须来自从节点"整类套用会把**主站自己的心跳 0x300 判成非法**。必须按具体帧语义分别判断（心跳 node=0、ACK node≥1）。
4. **事件风暴抑制跨窗口累加**：窗口到期放行时未清零 `repeat_count`，"距上次上报的重复次数"语义不成立。

## 测试框架约定

- `tests/harness/utest.h` 为**自注册**框架（MSVC `.CRT$XCU` / GCC `constructor`），避免"忘记登记 → 用例静默不跑"。新增用例只需写 `UTEST_CASE(唯一名){...}`，**不再需要维护任何用例列表**（旧的 `UTEST_SUITE_FUNCS` 已移除，切勿再加）。
- `tests/test_dbc_drift.c` 与 `tools/validate_dbc.py` 的"黄金报文"必须与 `tests/test_codec.c` 的字节断言保持一致；改动 wire 格式时三处同步。
- cantools 的注意点：有 `VAL_` 枚举表的信号，`decode()` 返回**枚举名字符串**（即使 `scaling=False`）；float 型信号（factor≠1）在 `scaling=False` 下才返回原始整数。位域信号不要建逐位 VAL_ 表（会被解析器当成互斥取值）。


## 协议细节速查（v1.0 定稿，勿凭记忆改）

- **10 帧 ID 表**：事件 0x011/0x021、命令 0x100(广播)/0x110/0x120、遥测 0x210/0x220、心跳 0x300、ACK 0x310/0x320。扩展节点三占 0x031/0x130/0x230/0x330。
- **可靠传输三件套**：命令帧 byte0 = seq（主站全局递增）；ACK 帧 byte0 = 回显 seq；重传 = 50 ms 窗口 × 最多 3 次；掉线 = 3 s 无帧。
- **⚠️ 幂等的两条铁律（v1.4 修复的两个静默丢命令缺陷，勿简化）**：① **seq 按通道分离**——广播 0x100 与单播 0x110/0x120 **各维护一个 last_seq**；共用一个会因 seq 仅 8 位、每 256 条回绕而撞号 → 节点判重复只回 ACK 不执行（主站收到 ACK 却没动作）；② **`seq_valid` 标志**——节点上电/软复位/OTA 跳转后 last_seq 无意义，须置 seq_valid=false，**第一个命令无条件执行**并记录后才启用重复判定，否则主站发 seq=0 会被误判重复而丢弃。
- **节点栈预算（20KB SRAM 硬约束）**：CAN_RX 2KB / CAN_TX 1KB / Sensor 1KB / Motor·Servo 2KB / Buzzer·Heartbeat 各 0.5KB + TCB/队列 ≈3KB ≈ **10KB 合计**，余 ≥4KB；启用 `configCHECK_FOR_STACK_OVERFLOW=2` + `uxTaskGetStackHighWaterMark()` 打 RTT；中断里禁 printf/浮点。
- **v1.3 协议增补（勿忘）**：心跳 byte5 = **协议版本**（与固件版本分离）；事件帧 byte7 = **重复计数** + **事件风暴抑制**（同一事件码最小间隔 200 ms，防最高优先级事件帧饿死总线）；**广播命令 0x100** 各节点回各自 ACK（0x310/0x320 ID 不同不冲突），主站按在线位图收齐、失败转单播；**掉线安全态**：电机=制动停、舵机=保持最后角度、蜂鸣器=停。
- **固件仓库分工（v1.3 澄清矛盾）**：**W25Q64 = 节点固件仓库**（多版本/多节点镜像）；内部 littlefs（storage 分区 ~7.5MB）= **仅日志**；ESP32 自身 OTA 直接写 ota_1 无需仓库。
- **bxCAN 验收滤波（零成本安全）**：F103 有 **14 组硬件滤波器**；节点只收 0x100/0x110(或0x120)/0x300，其余控制器层丢弃——安全建模"ID 白名单"的硬件落地；**Bootloader 与 App 滤波配置不同**（Bootloader 还要收 ISO-TP），跳转/进升级模式须重配。
- **IWDG 与 OTA**：IWDG 开了软件关不掉 → Bootloader 主循环与 ISO-TP 等待循环必须喂狗；升级期 IWDG 复位 = 升级失败，不写有效标志落回旧固件。
- **T-18 前移**：擦 flash 丢帧**先行实验已提到阶段 2**（裸片循环擦页 + 对端持续发帧数丢帧率），是 bootloader 架构（ISR 驻 RAM/拉模式）的决策前提；§7.2 的 T-18 是全链路完成后的正式验收。
- **CANopen 迁移映射表**（若深化）：0x000=NMT、0x080=SYNC、0x081/0x082=EMCY、0x181/0x182=TPDO1、0x201/0x202=RPDO1、0x581/0x582 与 0x601/0x602=SDO、0x701/0x702=Heartbeat。
- **负载率标度（500 kbps，135 bit/帧）**：2 节点 3 帧/s = 0.08%；8 节点 9 帧/s = 0.24%；要达 5% 需 8 节点各 ~23 Hz；达 20% 需 ~92 Hz。理论极限约 3700 帧/s → **常规遥测不是瓶颈，固件升级大块传输才是**。
- **ESP32-S3 16 MB 分区表**：nvs 0x9000/24K、otadata 0xF000/8K、phy_init 0x11000/4K、**ota_0 0x20000/4MB**、**ota_1 0x420000/4MB**、storage(littlefs) 0x820000/~7.5MB（放日志 + 固件仓库）。
- **节点 Flash 三方案**：A 纯片内 C8T6（Boot 12K + App A/B 各 24K + 标志 4K，**App 仅 24K 不推荐**）/ **B 换 CBT6 128KB（Boot 16K + App A/B 各 52K + 标志 8K，推荐）** / C 加 W25Q64 暂存。
- **升级流程七步**：请求升级→软复位进 Boot → 能力握手（芯片 ID/flash 容量/块大小/版本）→ 传元数据（大小/版本/CRC32 或 SHA-256）→ 分块传输（带块号+块级 CRC，窗口 N 块）→ 整包校验 → 写有效标志 → 软复位跳转（自检失败回滚）。
- **RTOS 任务数**：核心机 **7 个**（CAN_RX/CAN_TX/Control 10ms/IMU 20ms/Audio/UI 50ms/Storage 1s）；节点各 **6 个**（CAN_RX/CAN_TX/Sensor 100ms/Motor·Servo/Buzzer/Heartbeat 1s）。优先级按**速率单调**。
- **签名的层次区分（面试易混）**：Secure Boot v2 = 只运行我签名的代码；Flash 加密(XTS-AES) = 别人读不出固件；签名 OTA = 推来的镜像可信。三者独立可启用。

## 已核实的事实（勿再怀疑）

- ESP32-S3 内置 **1 个 TWAI** 控制器，无需外挂 MCP2515。TWAI **仅支持 Classic CAN，不支持 CAN-FD**。
- Classic CAN 标准帧：**111 bit**（无位填充）/ **135 bit**（最坏位填充，含帧间间隔）——来自 Linux 内核 CAN 子系统帧长定义。
- ESP32-S3 有 **2 个 I2S 控制器**；麦克风与功放共享 BCLK/WS 必须在同一端口，**但双端口独立时钟同样合法**——"必须单端口全双工"是伪两难。
- ESP32-S3-DevKitC-1 的 **BOOT 按键接 GPIO0**（非 GPIO9）；板载 WS2812 引脚**随板卡版本在 GPIO38/GPIO48 间变动**，不能当确定备用脚。
- Blue Pill 板载 3.3V LDO（RT9193）**最大仅 300 mA**。
- STM32F103 的 **ADC 引脚完全不支持 5V**（即使标称 FT 的引脚，模拟模式也不得超过 VDDA）→ AO 分压是**强制项**。
- STM32 **写/擦 flash 期间读 flash 会导致总线 stall**（ST 官方 Flash 编程手册 PM0059）。

## 已修复的错误（v1.0 修好，历史记录）

- CAN 帧 ID：原 `节点号<<4|帧类型` 与帧表不自洽（节点一被赋 16/17/26、节点二 16/18/26，超出 1~15）→ **重规划为 `类别(3)|节点号(4)|帧类型(4)`**：0x011/0x021 事件、0x100/0x110/0x120 命令、0x210/0x220 遥测、0x300 心跳、0x310/0x320 ACK。ID 升序 = 紧急度降序。
- 原文档称"心跳 0x010 优先级最高、事件与遥测同为最低"——**事实相反**：事件 0x110/0x120 的 ID 大于遥测 0x101/0x102，报警优先级反而更低。新方案已按紧急度排序。
- 心跳 ID（0x010/0x100 冲突）与 ACK ID（0x1A1/0x2xx 冲突）已统一。
- 备用引脚原列 GPIO12~15，实际已被 BTN2/I2S DIN/I2S DOUT/功放 SD 占满 → 已改为仅 GPIO9。
- 原 10 个帧 ID 中只有 4 个有字段定义 → **10/10 已全部定义**；命令帧与 ACK 帧新增 **seq 序号字段**实现幂等。
- 负载率原写 <5%（2 节点）/ <20%（8 节点），实际 **0.08% / 0.24%**（高估 60~80 倍）。
- 功耗原写"总 300~500mA@5V"与自身堵转数据矛盾 → 改为**分轨表**：逻辑轨典型 ~300/峰值 ~800 mA@5V；动力轨典型 ~550 mA/峰值 ~3.4 A（**电源建议 5V/5A，2A 不够**）。
- 时延原混为一谈 → 拆为"命令传输 <5ms"与"控制闭环（受 1s 遥测主导）"。
- SG90 原 PA8 方案被误称"与 PA9 周期配置冲突"——**不成立**（同定时器同频无冲突）；改用 TIM3_CH1/PA6 是更清晰的选择而非必需。

## OTA（本项目技术核心）

- **四条升级链路**：① ESP32-S3 自升级（A/B + otadata + rollback + 签名/Secure Boot v2）；② W25Q64 固件仓库；③ CAN 分段传输（ISO-TP / CANopen SDO Block）；④ STM32 节点 IAP Bootloader；全局串成**网关式 FOTA**（版本矩阵 + 失败隔离 + 断点续传）。
- **三条决定性约束**：① F103C8T6 **无双 bank**（不像 F4/F7/G4 有 BFB2）→ 必须自定义 A/B 或外部 flash 暂存；② 仅 **20KB SRAM** 装不下 64KB 固件 → 必须"边收边写 flash"；③ 擦 flash 时总线 stall → CAN RX 中断延迟可达 ~20ms，而 FIFO 只有 **3 个邮箱** → **会丢帧**，对策是把 CAN ISR 搬进 RAM（`.ramfunc`）+ 改用拉模式。
- **耗时结论**：64KB 镜像 500kbps 下 CAN 传输约 1.05s，flash 编程+擦除约 3s → **升级耗时由 flash 特性决定，不由总线带宽决定**（波特率提到 1Mbps 只省 ~0.5s）。预期实测 4~8s。
- **硬件建议**：C8T6 的 64KB 做"Boot+2×App+标志页"会把 App 压到 24KB，太紧 → 推荐 **STM32F103CBT6（128KB，引脚兼容）**，或给节点加 **W25Q64（约¥5）** 做双区暂存。
- **Bootloader 跳转顺序**：`__disable_irq` → 关 SysTick → 清 NVIC ICER → **清 NVIC ICPR（最易漏）** → `HAL_RCC_DeInit`/`HAL_DeInit` → `__set_MSP(*(uint32_t*)APP_ADDR)` → 跳 `APP_ADDR+4`；App 侧必须在最开头设 `SCB->VTOR`。

## 实际硬件 BOM（用户 2026.10.03 确认，与文档逐件吻合）

- 核心机：N16R8 + **TJA1050** + SSD1306 + MS4030 + MAX98357 + W25Q64 + MPU6050 + EC11（无按键）+ 3 按键；节点一/二：C8T6 + **TJA1050** + 各外设。
- **3 片 TJA1050 全部在用** → P0-① 电平问题**现实存在**。**用户已决策（2026.10.03）：保留 TJA1050 ×3 做电平处理**——RX **先串 1kΩ 限流**（注入 ~1.1 mA，靠 ESD 钳位；**不达标再补 2kΩ 对地组成 1k/2k 分压**）；TX 直连 3.3V（低于 VIH≈3.5V 规范下限，超规格，**逐片实测**，典型阈值 2.0~2.5V 通常可用）；验证 = 125kbps 波形核对 → 500kbps 30min 无错误帧 → Bus-Off 恢复；不稳定单路单独换 3.3V 收发器。**项目文档已升 v1.1**（§9.1/BOM/§3/§11.2 同步改写）。
- **模拟模块全部 3.3V 供电** → AO ≤3.3V **可直连 ADC**（§9.5 的"5V 必须分压"条件不触发，但 DO 阈值需逐个电位器标定）。
- 已确认不可换型项：N16R8（GPIO33~37 已按占用避让）、C8T6 ×2（OTA 走方案 B/C）、MPU6050（上电先验 WHO_AM_I=0x68）、SSD1306（先 I²C 扫描排除 SH1106）、EC11 无按键。

## 硬件与采购关键点

- **N16R8 坑**：GPIO33~37 被 **Octal PSRAM** 占用；GPIO19/20=USB；GPIO26~32 内接 Flash；GPIO0/3/45/46 为 strapping。
- **⭐ PSRAM 模式决定 GPIO33~37 是否可用**：N16R8/N8R8 是 Octal → 占用；**N8R2 是 Quad（与 Flash 共用内部 SPI）→ GPIO33~37 空闲**。本项目无大词汇量语音模型，2MB PSRAM 够用，**选 N8R2 可让引脚规划宽松很多，v0.2 的引脚返工本可避免**。
- **切勿买 ESP32-S3-WROOM-2（N32R16V 类）**：Flash/PSRAM 为 1.8V，**IO47/IO48 属 VDD_SPI 域仅输出 1.8V**，与用 GPIO47 做 BTN3、GPIO48 关联 WS2812 的引脚表冲突。
- **供电红线**：SG90 堵转 650~700mA、浪涌~1A；电机堵转 1.2A/通道；必须分轨 + 独立 5V/5A + 肖特基隔离 + 共地。
- **硬件缺口**：承诺"堵转电流检测"但 BOM 无电流采样（TB6612 无电流输出）；承诺"电机 PID"但无编码器；缺 RTC、SWD 排针、终端电阻/连接器、USB-CAN 分析仪。
- **采购防坑**：1.3" OLED 常是 SH1106（非 SSD1306，偏移 2 像素）；MPU6050 翻新多，先验 WHO_AM_I(0x75)=0x68；CAN 的 H/L/GND **必须焊接/压接**，不可用面包板杜邦线，原型先用 125kbps。
- **现成资源（勿从零造轮子）**：CANopen 用 **CANopenNode**（官方 **CanOpenSTM32** 移植）；差分 OTA 用 **esp_delta_ota**；PC 侧用 can-utils/SavvyCAN/cantools/python-can/pytest；**调试图省串口用 SEGGER RTT**（走 SWD，OpenOCD 已支持，不需 J-Link）——正好解决节点一无 USART1、节点二 PA2/PA3 被占的问题。

## 设计约定

- **代码骨架**：协议库必须**零 HAL 依赖**（纯 C）才能 PC 单元测试 + 两块 MCU 共用；**禁用 C 位域解析报文**（布局实现定义、跨编译器不可靠），用手写移位掩码；协议内统一小端；错误码统一枚举；协议库不用 malloc。
- **物理层**：500kbps、**采样点 87.5%**；STM32F103 参数 **P=9 / BS1=6 / BS2=1 / SJW=1（8 tq/bit，36MHz APB1）**——⚠️ bxCAN 的 TS1 仅 4 bit（BS1≤16 tq），24 tq 的 TS1=20 方案**不可实现**（v1.2 已修）；ESP32 侧 `TWAI_TIMING_CONFIG_500KBITS()` 宏采样点仅 **80%**，须自定义 `brp=20/tseg_1=6/tseg_2=1/sjw=1`（80MHz÷(20×8tq)=500k）；两端 120Ω（建议分裂终端 2×60Ω+4.7nF 到地）；支线 <0.3m。
- **I2C**：SSD1306 + MPU6050 同总线需 SDA/SCL 各加 **4.7k 外部上拉**（ESP32 内部约 45k 偏弱）。
