- **⭐ 最重要的新发现（采购决策）**：**PSRAM 是 Octal 还是 Quad 决定 GPIO33~37 是否被占用**。N16R8/N8R8 = Octal PSRAM → 占用 GPIO33~37；**N8R2 = Quad PSRAM（与 Flash 共用内部 SPI）→ GPIO33~37 空闲**。本项目无大词汇量语音模型，2MB PSRAM 够用 → **选 N8R2 可避免 v0.2 的引脚返工**。另核实：**WROOM-2（N32R16V）的 Flash/PSRAM 是 1.8V，IO47/IO48 属 VDD_SPI 域仅输出 1.8V**，而引脚表用 GPIO47 做 BTN3、GPIO48 标 WS2812 → 买错板子会不兼容，务必坚持买 WROOM-1。

**测试抓出的 6 个真实缺陷**（面试可讲"被测试/交叉编译抓出来"）：

1. **占空比四舍五入方向写反**：`(param+50)/10` → 500 变55% 而非 50%（+50 是给"×10→%" 用的，
   但协议给的 param 本身就是 0.1% 标度，再加就整体多 5 个百分点）。
2. **温标量化用截断而非四舍五入**：`(int16_t)(t_c*10.0f)` 是向零截断，误差恒为 **−0.1℃**
   （单向偏低，比随机误差更难发现，容易被误判成"传感器不准"）。
3. **valid 位误清到 status 寄存器**：传感器故障时 `clear_bit(&status_bits, VALID_TEMP_BIT)`，
   跨寄存器误操作 → 故障时 valid 仍为 1，主站继续相信已停更的温度。
4. **事件抑制闸门被两事件共用**：`proto_event_should_report` 有状态（首次调用会打开窗口），
   过温与传感器故障共用一个 throttle → 同一次心跳里第二次调用必然被压制，
   **高优先级事件把低优先级饿死**。注释写"不共享"但代码共享了。已改为每事件码一个闸门。
5. **`PROTO_STATIC_ASSERT` 单层宏拼接**：`typedef char x_##__LINE__[]` 中 `##` 阻止 `__LINE__`
   展开 → 所有断言共用一个 typedef 名 → GCC + C99 + `-Wpedantic` 报 *redefinition of typedef*。
   **PC(MSVC/C11) 完全不触发** = 典型"换编译器才炸"。修法：双重宏展开（CAT 两层），
   且不能用 `_Static_assert`（C99 + -Wpedantic 会拒）。
6. **`extern` 声明写在函数体内** → MSVC C4210 非标准扩展。提升到文件作用域。

## 节点一固件接入真实 MCU 工程（用户提示"项目内有节点的 MCU 工程"）

**先纠正我自己的一个误判**：前一轮我把 `git status` 输出截断到 12 行，误以为 `CAN_Node1/2`、
`CAN_ESP32/`、`SimpleGUI-Stable/` **没被 git 跟踪**。实际它们在 `git status --short` 里以
`?? CAN_Node1/` 的形式存在（未跟踪、也未被忽略）。**教训：截断输出后不要对"有没有"下结论，要用 `git status --ignored` 看全量。**

**仓库实况（本轮查明）**：
- `CAN_Node1/`、`CAN_Node2/` = 用户原有的 **CubeMX 空骨架**：CMake + Ninja + arm-none-eabi 工具链，
  `.ioc` 只配 PD0/PD1 晶振 + PA13/PA14 SWD，`main.c` 主循环空，**零外设**；基线可编译
  （RAM 1584 B / FLASH 3644 B）。两个工程的 `Core/` 与 `gpio.c` 完全相同。
- `CAN_ESP32/hello_world/` = ESP-IDF 官方模板，未动。
- `SimpleGUI-Stable/` = 与 CAN 项目无关的第三方 GUI 库，不动。
- 结论：**CubeMX 工程与 `firmware/` 是分层关系，不是重复劳动**——前者提供 HAL 驱动与
  `main()`/时钟，后者提供协议、业务、调度与外设行为。

**本轮完成（CAN_Node1 已能交叉编译出可烧 ELF，零告警）**：
1. **补齐缺失的 HAL 驱动**：原工程只拷了"已配外设"的源码，缺 CAN/ADC/TIM/IWDG/UART。
   从 `C:\Users\Administrator\STM32Cube\Repository\STM32Cube_FW_F1_V1.8.7` 拷入**含 _ex 变体**

3. **BSP 适配 CubeMX 工程**：拆出 `node1_bsp_init_system()`（按 `SystemCoreClock` **实测值**

   `HAL_ADC_Enable/Disable`**，校准由 `HAL_ADCEx_Calibration_Start` 内部完成 Enable）；
